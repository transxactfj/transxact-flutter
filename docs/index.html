FLUTTER SDK

Payments made easy.
In your Flutter app.

Take M-PAiSA and MyCash payments in FJD with Transxact hosted Checkout Sessions. Your app never holds a secret key and never sets an amount.

01 — How it works

Two legs. Your server in the middle.

The package covers the two parts of a payment that happen in your app. Everything that needs a secret key stays on your Merchant backend.

PAY

Create and open

Ask your backend to create a Checkout Session, then open its hosted page in an in-app browser: Chrome Custom Tabs on Android, SFSafariViewController on iOS.

RETURN

Ask, don’t assume

When the Customer comes back, your backend is asked what really happened. The return link is only a hint, never proof of payment.

FULFIL

Trust the webhook

Fulfil orders from signed webhooks on your server. The app only shows the Customer the outcome.

1 · AppTaps Pay
2 · Your backendCreates the session with your key
3 · TransxactHosted page takes the payment
4 · AppBackend confirms the status
02 — Quickstart

Three pieces of code.

Point the SDK at your backend, add a button, and show the result.

1 · Configure

Use URLs for a simple backend, or your own functions when it needs a different request shape. The SDK sends one Idempotency-Key per attempt.

final transxact = Transxact(
  createSessionUri: Uri.parse('https://shop.example/api/checkout'),
  retrieveSessionUri: Uri.parse('https://shop.example/api/checkout'),
);

2 · Pay button

Say what is bought. The amount is decided by your backend, where the Customer can’t edit it.

CheckoutButton(
  transxact: transxact,
  payload: {'orderId': order.id}, // never an amount
  onCreated: (created) => pendingSessionId = created.id,
  onError: (error) => showError(context, error),
  child: const Text('Pay with M-PAiSA or MyCash'),
)

3 · Return screen

Polls your backend while the session is pending, then settles on succeeded, failed or cancelled.

CheckoutReturnBuilder(
  transxact: transxact,
  sessionId: sessionId,
  builder: (context, update, refresh) {
    if (update.state == CheckoutReturnState.settled) {
      return Text(update.session!.status.name);
    }
    return const CircularProgressIndicator();
  },
)
03 — Safety rules

Built so the unsafe thing can’t happen.

These rules are part of the SDK’s design and are covered by its tests.

No secret keys

The SDK never holds a Transxact key and never accepts an sk_ key. A secret key can’t live safely in a mobile app.

No amounts

The app says what is bought. Prices are decided on your Merchant backend.

Checked links only

The hosted URL must be https (or loopback http for local development) before it is opened.

One key per attempt

A retry after a lost response replays the same Checkout Session, so no double charges.
