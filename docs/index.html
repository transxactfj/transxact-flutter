FLUTTER SDK

Payments made easy.
In your Flutter app.

Take M‑PAiSA and MyCash payments in FJD with Transxact hosted Checkout Sessions. Your app never holds a secret key and never sets an amount.

Get started View on GitHub
flutter pub add transxact_flutter
01 — How it works

Two legs. Your server in the middle.

The package covers the two parts of a payment that happen in your app. Everything that needs a secret key stays on your Merchant backend.

PAY

Create and open

Ask your backend to create a Checkout Session, then open its hosted page in an in-app browser: Chrome Custom Tabs on Android, SFSafariViewController on iOS.

RETURN

Ask, don’t assume

When the Customer comes back, your backend is asked what really happened. The return link is only a hint, never proof of payment.

FULFIL

Trust the webhook

Fulfil orders from signed webhooks on your server. The app only shows the Customer the outcome.

1 · AppCustomer taps Pay
2 · Your backendCreates the session with your key
3 · TransxactHosted page takes the payment
4 · AppBackend confirms the status
02 — Quickstart

Four pieces of code.

Point the SDK at your backend, add a button, show the result, and give your backend one route.

1 · Configure

Create one Transxact and share it with the button and the return screen. Use URLs for a simple backend, or your own functions when it needs a different request shape.

The SDK sends one Idempotency-Key per attempt for your backend to forward.

final transxact = Transxact(
  createSessionUri: Uri.parse('https://shop.example/api/checkout'),
  retrieveSessionUri: Uri.parse('https://shop.example/api/checkout'),
);

2 · Pay button

Say what is bought. The amount is decided by your backend, where the Customer can’t edit it.

The button is disabled with a spinner while it works, so repeat taps are ignored. onCreated hands back the session id to check later.

CheckoutButton(
  transxact: transxact,
  payload: {'orderId': order.id}, // never an amount
  onCreated: (created) => pendingSessionId = created.id,
  onError: (error) => showError(context, error),
  child: const Text('Pay with M-PAiSA or MyCash'),
)

3 · Return screen

Polls your backend while the session is pending, then settles on succeeded, failed or cancelled.

update.state is what the lookup is doing; session.status is the payment.

CheckoutReturnBuilder(
  transxact: transxact,
  sessionId: sessionId,
  builder: (context, update, refresh) {
    if (update.state == CheckoutReturnState.error) {
      return TextButton(onPressed: refresh, child: const Text('Try again'));
    }
    if (update.state != CheckoutReturnState.settled) {
      return const Text('Confirming your payment…');
    }
    return Text(update.session!.status.name);
  },
)

4 · Merchant backend

The one piece that runs on your server, not in the app. It uses @transxact/node and your secret key.

It looks up the price, forwards the Idempotency-Key, and reports the status. A runnable version is in the example app. This one uses Node.

// server.mjs — server-only
import { TransxactApiClient } from "@transxact/node";

const transxact = new TransxactApiClient({ token: process.env.TRANSXACT_SECRET_KEY });
const ORDERS = { order_1001: { totalCents: 2500 } }; // your own price list

// POST /api/checkout
const { orderId } = await readJson(req);
const session = await transxact.checkoutSessions.create({
    idempotencyKey: req.headers["idempotency-key"] ?? randomUUID(),
    amount: ORDERS[orderId].totalCents,
    currency: "FJD",
    successUrl: "https://shop.example/checkout/return",
    cancelUrl: "https://shop.example/checkout/return",
});
send(res, 200, { id: session.id, hostedUrl: session.hostedUrl });

// GET /api/checkout?session_id=cs_…
const found = await transxact.checkoutSessions.retrieve({ id });
send(res, 200, { id: found.id, status: found.status });
03 — Safety rules

Built so the unsafe thing can’t happen.

These rules are part of the SDK’s design and are covered by its tests.

No secret keys

The SDK has no key option, never accepts an sk_ key and never calls Transxact. Every request goes to your Merchant backend.

No amounts

The app says what is bought. Prices are decided on your Merchant backend.

Checked links only

The hosted URL must be https (or http on localhost, 10.0.2.2 or *.localhost for local development) before it is opened.

One key per attempt

A retry after a lost response replays the same Checkout Session, so no double charges.

No double taps

The button is disabled while it creates a session and opens the browser. Repeat taps are ignored.

Request errors aren’t payment failures

A failed lookup is CheckoutReturnState.error; a failed payment is CheckoutSessionStatus.failed. They can’t be confused.

04 — API

One class, two widgets and one error type.

At the same level, a function beats a URL. The widgets are thin wrappers over Transxact, so you can also call it directly.

Transxact

Holds your backend setup and does the work for the widgets.

ParameterWhat it does
createSession / createSessionUriYour function, or a URL, for creating a Checkout Session. It must return hostedUrl
retrieveSession / retrieveSessionUriYour function, or a URL, for looking one up. It must return status
headersExtra headers for the URL shorthands, e.g. your own auth
pollingPollingOptions(interval, maxInterval, timeout)

pay({payload}) creates the session and opens it. fetchSession(id) does one lookup. watchSession(id) streams updates, and cancelling it stops polling.

CheckoutButton

Starts a Checkout attempt and opens the hosted page.

Option
payloadWhat is being bought — never the price
onCreatedReceives the session id and hostedUrl once the page has opened
onErrorCalled when starting the payment fails

CheckoutReturnBuilder

Runs watchSession and polls with backoff (1.5 s, doubling to 8 s) for up to 60 s.

Option
sessionIdThe session to check. Changing it restarts the lookup
builderCalled for every update with a refresh function
loading→polling→settledortimedOuterror

TransxactException

Errors raised by the SDK carry a code. Errors thrown by your own functions pass through unchanged.

codeWhen
configMissingNeither a function nor a URL says how to reach your backend
httpErrorA URL shorthand got a non-2xx response; status and body are set
invalidResponseThe response isn’t a JSON object, or has no valid hostedUrl or status

The full reference is in the README and the API docs on pub.dev.

05 — Try it

Try every outcome in Test mode.

Use an sk_test_ key on your Merchant backend: Test mode runs simulated payments on a practice screen and moves no money. Run the example app against the sample backend, or drive a session to succeeded, failed or cancelled yourself, then open your return screen with that session id.

curl -X POST https://api.transxact.io/v1/checkout-sessions/cs_…/test-transition \
  -H "Authorization: Bearer $TRANSXACT_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status":"succeeded","provider":"mpaisa"}'
